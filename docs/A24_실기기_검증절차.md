# A24 실기기 검증 절차

설계 11 ‘A24 필수 실통화 시험 절차’를 이 저장소 도구로 수행하는 방법이다.
**이 절차를 통과하기 전에는 운영 조직에서 발신 시작 버튼이 잠겨 있다.** 결과는 사람이 원격 단말로 듣고 기록한다.

## 0. 준비
- 내부 승인을 받은 **시험 번호**(원격 시험 단말)와 원격 청취자 1명
- Windows PC에 Android platform-tools(adb), 이 저장소 설치(`scripts/setup.ps1`), `pip install -e ".[voice]"`
- A24: 개발자 옵션 → USB 디버깅 허용, PC와 USB 연결, PC에서 `adb devices`로 `device` 상태 확인
- 웹 관리화면: **운영 조직**으로 만들고 설정 > 단말에서 ‘갤럭시 A24’ 등록(이 PC에 바로 연결 체크)

## 1. 환경 수집 (사실 기록)
```
aicc-probe env
```
기록되는 것: 모델(SM-A245…), Android/One UI 버전, 통신사, PC OS, precise call state 노출 여부, PC 오디오 장치 목록·기본 출력 장치.
`unknowns` 항목은 그대로 남겨 둔다.

## 2. 발신·응답감지·종료
```
aicc-probe call --number 010XXXXXXXX --approved
```
원격 청취자가 약 10초 뒤 전화를 받는다. 로그에서 **받기 전에는 DIALING/ALERTING, 받은 순간 ACTIVE** 로 바뀌는지 본다.
OFFHOOK(mCallState=2)만 보이고 precise 상태가 없으면 응답 감지는 **불가**로 판정한다(이 경우 오프닝을 응답 전에 재생할 위험이 있어 실발신 금지).

## 3-1. RX(상대 음성) — scrcpy
scrcpy 5.0.1을 설치하고(PATH 또는 `.aicc\agent.env`의 `AICC_SCRCPY`) 다음을 실행한다.
```
aicc-probe rx --number 010XXXXXXXX --approved
```
scrcpy를 `--no-window --no-playback --audio-source=voice-call-downlink --audio-codec=raw`로 띄워 상대 음성만 USB로 받는다.
PC 스피커로는 재생하지 않으며, 저장된 `probe_rx_scrcpy_*.wav`를 헤드셋으로 들어 원격 문장이 들리는지 확인한다.

## 3-2. TX(ARS 송출)
scrcpy에는 PC 소리를 통화로 보내는 기능이 문서에 없다. 이전 PC에서 상대가 AI 음성을 들은 경로를 확인해 `AICC_TX_DEVICE`로 지정한다.

## 3. (대안) 사운드카드 RX/TX 오디오
USB 케이블만으로 통화 음성이 PC 오디오 장치로 나타나는지가 핵심 가설(H1)이다. 공식 문서상 USB 디버깅 연결 자체는 오디오를 주지 않으므로, **장치 목록에 통화 음성용 입력/출력이 새로 나타나지 않으면 이 단계는 실패**로 기록한다.
장치가 있다면:
```
aicc-probe audio --number 010XXXXXXXX --rx <입력장치> --tx <출력장치> --approved
```
- TX 출력으로 PC 기본 스피커·헤드폰을 지정하면 도구가 거부한다.
- 원격 청취자는 TX 시험음을 처음부터 끝까지 들었는지 말해 준다.
- 원격 청취자가 시험 문장 10개를 읽고, 저장된 `probe_rx_*.wav`에서 PC 마이크가 아닌 통화 음성으로 들리는지 확인한다.
- 통화 중 PC 스피커에서 아무 소리도 나지 않았는지 확인한다.

## 4. 반복과 업로드
같은 환경(케이블·PC·장치 번호 고정)에서 2~3 단계를 **10회 이상** 반복하고 케이블 제거·재연결·재부팅도 시험한다.
```
aicc-probe upload --server http://127.0.0.1:8765 --token <장치 토큰>
```
웹 설정 > 단말 > ‘실통화 검증 결과 기록’에 RX·TX·PC 무음·녹음 확인 여부, 시험 횟수(10회 이상), 원격 청취자를 입력한다.
단말 능력 보고가 바뀌거나 다른 기기(일련번호)가 연결되면 검증 기록은 자동으로 무효가 된다.

## 5. 실패 시 보고 형식
| 항목 | 사실 | 가설 | 대안(요구 변경 아님, 결정 필요) |
|---|---|---|---|
| RX/TX | 장치 목록에 통화 음성 장치 없음 | 일반 앱·ADB로는 통화 오디오 경로 접근 불가 | 별도 USB 오디오 장치(케이블 외 추가 장비), 제조사 기능, 통신사 전화 API |
| 응답 감지 | precise 상태 미노출 | One UI 버전 제한 | 원격 음성 감지 기반 판정(오인 위험 검증 필요) |

AUX·블루투스·스피커폰 우회는 원래 요구 충족으로 인정하지 않는다(설계 01).
