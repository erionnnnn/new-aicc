### 핵심 판단

웹에서 명부와 통화 결과를 관리하고, 하나의 PC 프로그램이 A24 연결을 맡는 구조를 제안합니다. 단, USB 케이블만으로
실제 통화 음성을 양방향 처리할 수 있는지는 먼저 실기기로 입증해야 합니다. GitHub 연결이나 화면 제작만으로 통화 품
질이 완성되지는 않습니다.
근무확정일은 상대가 확인한 다음 근무 가능일로 임시 정의합니다. 실제 배정 확정일을 뜻한다면 두 값을 분리해야 합니다.
이전 날짜는 보존하고 확인 근거와 변경 이력을 남깁니다.

## 01 사업기획서


### 목적과 사업 범위

간병사에게 실제 전화를 걸어 현재 근무 여부, 근무 종료일, 다음 근무 가능일을 확인하고 엑셀 명부를 갱신하는 내부 업무
용 AICC다. 병원 배정이나 고용계약 확정을 대신하지 않으며, 전담 실장의 배정 업무와 일정 확인 업무를 분리한다.
운영자는 엑셀을 올리고 대상자를 선택한 뒤 통화를 시작한다. 시스템은 녹음 ARS를 중심으로 대화하고 예외 질문만
Gemini Live API로 응대한다. 통화 결과와 녹음을 검토한 후 갱신된 명부를 내려받는다.


### 사용자 확정 요구와 설계 제안

확정 요구: 갤럭시 A24 실전화, USB 통화 입출력, AUX 미사용, 통화 중 PC 스피커 미출력, 단일 실행, 남녀 녹음 선택, AI
예외 응대, 통화 녹음, 연락거부, 엑셀 업로드와 다운로드.
설계 제안: Windows PC의 통합 실행 프로그램이 웹 관리화면을 열고 연결 에이전트를 함께 실행한다. Windows는 현재
임시 가정이며 실제 운영 PC 확인 후 고정한다. A24 한 대당 동시 통화는 한 건으로 제한한다.

GitHub는 소스코드와 버전 관리 수단이다. GitHub 연결 자체가 전화 기능이나 서버를 제공하지 않는다. GitHub Pages
같은 정적 호스팅만으로 전화·DB·비밀키 처리를 완성할 수 없다.


### 기대 효과와 측정 방법

수작업 전화 및 재입력 시간을 줄이고 명부의 최신성을 높이는 것이 목표다. 절감 효과는 아직 측정되지 않았다. 같은 대상
조건에서 수동 처리와 AICC의 운영자 투입 시간, 유효 일정 확보율, 잘못된 날짜 반영률을 비교한다.
월 비용은 서버·DB·녹음 저장료, STT 사용량, 예외 AI 사용량, 휴대폰 요금, 유지보수 인력으로 계산한다. 가격과 처리량은
미확정이므로 금액을 임의 제시하지 않는다.


### 개발 순서와 중단 기준

1단계는 A24 실기기에서 수신 음성 추출·송신 음성 전달·녹음·무음 라우팅을 검증한다. 2단계는 명부와 ARS 상태 흐름, 3
단계는 예외 AI와 녹음, 4단계는 승인된 시험 대상 파일럿이다.
1단계가 실패하면 USB 조건을 충족했다고 주장하지 않고 원인과 가능한 대안을 보고한다. 별도 USB 오디오 장치가 필요
한 경우에도 추가 장비 없는 케이블 연결과 구분한다. AUX·블루투스·스피커폰 우회는 원래 요구 충족으로 인정하지 않는
다.


### 책임과 산출물

기획 담당은 날짜 의미와 대화 정책을 관리하고, 개발 담당은 USB 경로와 상태기계를 구현하며, 운영 담당은 녹음·결과를
검수한다. 이번 산출물은 설계 문서다. 프로그램 구현, GitHub 연결, 배포, 실통화 검증은 완료하지 않았다.


## 02 요구사항 정의서 PRD


### 제품의 완료 조건

운영자가 별도 터미널이나 여러 실행 파일을 켜지 않고 한 프로그램에서 업로드부터 결과 다운로드까지 처리해야 한다. 실
제 통화 기능은 USB 실기기 검증을 통과해야 활성화한다. 연결 표시만으로 통화 준비 완료를 표시하지 않는다.

### 날짜 의미의 기본 가정

입력의 ‘근무확정일’은 이 제품에서 ‘상대가 확인한 다음 근무 가능일’을 나타내는 기존 엑셀 열로 임시 해석한다. 실제 배정
확정일을 뜻하는 자료라면 자동 연결을 끄고 별도 ‘다음근무가능일’ 열에 기록해야 한다. 업로드 화면에서 이 의미를 명시하
고 매핑하도록 한다.
현재 근무 종료일과 다음 근무 가능일은 별도 저장한다. “25일까지 일해요”만으로 26일 가능을 추정하지 않는다. “언제든
가능”은 상시 가능 상태로 보관하며 임의 날짜를 확정하지 않는다.


### 품질 목표와 측정 경계

아래 값은 설계 목표이며 달성 실적이 아니다. 오프닝은 원격 응답 확인부터 원격 단말에서 소리가 시작될 때까지 p95 1초
이내, 일반 ARS는 상대 발화 종료부터 원격에서 답변이 들릴 때까지 p50 0.8초·p95 1.5초 이내를 목표로 한다.
AI 예외 응답은 같은 경계로 p95 3초 이내를 목표로 하며 초과 시 짧은 대기 안내 후 제한 시간에 종료한다. 날짜 자동 반영
의 오기입은 검증 세트에서 0건, 연락거부 재발신은 0건을 출시 기준으로 둔다. 무음 출력과 개인정보 유출 시험은 모두 통
과해야 한다.


### 데이터와 운영 제한

xlsx만 MVP에서 지원하고 xlsm·실행 매크로·암호화 파일은 거절한다. 초기 제안 한도는 파일 10MB, 1만 행이며 성능 시
험 후 조정한다. 재시도는 기본 자동 실행하지 않고 운영자 선택으로 큐를 만든다.


### 이번 범위에서 제외

병원·환자 매칭, 일자리 배정 확정, 급여 협상, 계약 체결, 다중 단말 동시발신은 MVP 범위 밖이다. 녹음이 없거나 AI가 실
패해도 날짜를 추정해 완료로 처리하지 않는다.


## 03 사용자 유형 정의서


### 운영자

간병사 명부를 업로드하고 발신 대상·목소리를 고른다. 통화 진행과 실패 사유를 보고 결과를 내려받는다. 대상 선택 실수
와 잘못된 날짜 저장이 가장 큰 위험이다. 시작 전 대상 수·연락거부 제외 수·장치 준비 상태를 함께 확인한다.


### 일정 검수자와 전담 실장

일정 검수자는 미확인 날짜와 대화 내용을 확인하고 필요한 경우 수동 수정한다. 전담 실장은 병원 배정이나 실제 근무 확정
업무를 맡는다. 자동 일정 확인 담당과 전담 실장은 다른 역할이며 AICC가 배정을 약속하지 않는다.


### 관리자

계정·권한·기기·ARS 음원·AI 설정·보관 기간을 관리한다. 비밀키 원문은 조회 화면에 표시하지 않는다. 음원 교체는 버전으
로 관리하고 현재 진행 중인 통화는 시작 당시 버전을 유지한다.


### 간병사

프로그램 계정이 필요하지 않다. 전화를 받아 일정에 답하고, 통화를 중단하거나 앞으로 연락하지 말라고 요청할 수 있다.
다른 사람의 번호이거나 잘못 연결됐다고 하면 일정 수집을 중단하고 번호 확인 대상으로 기록한다.


### 음성 안내 인물

여성 안내 역할 이름은 ‘김태희 실장’이다. 사용자가 정한 업무상 안내 이름이며 특정 유명인 목소리 사용을 의미하지 않는
다. 승인된 녹음만 사용한다. 남성 안내 이름은 미정이므로 발신 전 관리자가 등록한다.
오프닝 초안: “안녕하세요. [회사명]에서 근무 일정 확인을 맡고 있는 김태희 실장의 자동 안내입니다. 전담 실장님과는 별
도로 다음 근무 가능 일정을 확인드리고 있어요. 잠시 통화 괜찮으실까요?”
회사명은 미제공 상태다. 미입력 또는 임시 문구가 남은 음원으로 실제 발신하지 못하게 한다. 녹음 안내 방식은 운영 정책
확정 후 오프닝에 결합한다.

### 성공하는 사용자 경험

운영자는 오류 행만 수정하고 정상 행을 재입력하지 않는다. 검수자는 날짜의 근거 문장과 녹음 시점을 바로 확인한다. 간
병사는 긴 설명 없이 일정 확인을 마치거나 연락거부를 명확히 전달할 수 있다.

### 업로드 처리 상세

간병인 번호는 문자열로 보관한다. 연락처는 숫자·국가번호를 정규화하되 원본 문자열도 유지한다. 앞자리 0이 이미 손실
된 경우 임의 복원하지 않고 오류로 표시한다. 같은 간병인 번호에 서로 다른 연락처가 있으면 검수 대상으로 둔다.
같은 연락처에 여러 이름이 연결되면 자동 합치거나 연속 발신하지 않는다. 사용자 확인 후 하나의 발신 대상으로 묶되 원본
행 연결은 보존한다. 같은 파일 재업로드 시 파일 해시와 행 키를 이용해 중복 캠페인 경고를 제공한다.


### ARS 음원 구성

필수 키: opening, ask_working, ask_end_date, ask_available_date, confirm_date, ask_repeat, explain_role,
callback, refusal_ack, closing, ai_wait, ai_failed.
남녀 음원 묶음에 필수 키가 빠지면 해당 묶음으로 발신할 수 없다. 날짜 재확인은 월·일 조각 음원 또는 별도 승인된 날짜
음성 합성으로 구현한다. 조각 연결이 부자연스러우면 고쳐야 하며, AI 예외 응대와 날짜 읽기 방식을 혼동하지 않는다.


### 엑셀 출력 규칙

‘명부’ 시트는 원본 행 순서를 유지하고 확정된 날짜만 지정 열에 반영한다. 추가 열은 현재근무상태·근무종료일·다음근무가
능일·확인상태·통화결과·연락거부·마지막통화시각·검수메모다.
‘통화이력’은 통화별 한 행, ‘변경이력’은 기존 날짜·새 날짜·근거·확인자·시각, ‘오류행’은 업로드 오류를 담는다. 부재중·실패
·불명확·연락거부 행은 기존 근무확정일을 보존한다. 보존 값이 이번 통화에서 재확인된 값으로 보이지 않게 확인상태를 표
시한다.
모든 통화 완료 후 내려받기가 기본이며 도중에도 ‘진행 중 결과’ 표시로 내려받을 수 있다. 수식·외부 링크를 실행하거나 복
제하지 않고 값 기준으로 내보낸다. 서식의 완전 재현은 MVP 보장 범위가 아니다.

### 우선순위와 중복 방지

연락거부·종료 의도를 가장 먼저 처리한다. 그 다음 잘못된 상대, 끼어들기, 현재 질문의 답, 예외 질문 순서로 판단한다. 단
순 “네”는 현재 질문에 대한 동의일 때만 해석한다. 턴 번호와 통화 ID가 다른 인식 결과는 버린다.
ARS 재생 중 상대가 말을 시작하면 검증된 끼어들기 정책에 따라 송출을 멈추고 듣는다. 자체 송출 음성을 상대 발화로 인
식하지 않게 RX 경로를 분리하고 에코 억제를 검증한다.


### 예외 처리

침묵은 제안값 6초 후 재질문, 최대 2회 후 미확인 종료다. 상대 발화 길이에 일률적으로 1초 제한을 두지 않는다. 인식이
흔들리면 재확인하고 두 번 실패하면 검수 대상으로 남긴다.
AI는 예외 질문에 짧게 답한 뒤 저장된 복귀 상태로 돌아간다. AI가 응답하지 않거나 제한 시간이 지나면 실패 안내를 재생
하고 미확인 종료 또는 상담 요청으로 기록한다. AI가 DB 날짜를 직접 확정하지 않는다.


### 날짜 예시

2026년 10월 24일 통화에서 “다음 주 월요일”은 10월 26일 후보로 해석한 뒤 “10월 26일부터 근무 가능하신 게 맞으실
까요?”로 확인한다. “월말쯤”은 날짜 범위 후보로만 남기고 날짜를 묻는다.
“오늘까지 근무하고 내일부터 가능해요”는 종료일과 가능일을 각각 후보로 저장한다. ‘예’로 확인하기 전에 끊기면 기존 확
정일을 유지한다. 같은 통화에서 여러 일정을 말하면 마지막으로 명확히 확인한 값을 사용하고 전체 정정 이력은 보존한다.

### 통화 진행 화면 배치

상단은 캠페인 이름과 완료 0 / 전체 0, 중앙 왼쪽은 현재 간병사와 질문 상태, 중앙 오른쪽은 인식문장과 날짜 후보, 하단은
대기·완료 목록이다. 개인정보는 해당 역할의 범위에서만 표시한다.


‘일시정지’는 현재 통화를 끝낸 뒤 다음 발신을 멈춘다. ‘즉시중단’은 현재 송출과 발신 대기열을 즉시 중지하고 종료 명령을
보낸다. 종료 확인 전에는 ‘통화 종료 확인 중’으로 표시한다. 케이블이 빠져 종료 명령을 못 보내면 A24에서 직접 종료하도
록 안내한다.


### 결과 검수 화면

왼쪽에 원본 근무확정일과 이번 후보, 오른쪽에 근거 발화와 녹음 시각을 둔다. 확정·보류·수동수정 버튼은 역할별로 제한
한다. 수동수정에는 사유를 필수로 받고 원래 값을 덮어 기록에서 없애지 않는다.
날짜 후보가 비어 있으면 ‘미확인’으로 표시한다. 낮은 신뢰도, 날짜 범위, 상대의 확인 없는 후보에는 자동확정 표시를 붙이
지 않는다. 이미 다른 운영자가 바꾼 기록은 충돌 안내와 최신 값 비교를 제공한다.


### 재생과 오류 상태

녹음은 자동재생하지 않는다. 통화가 진행 중이면 재생 버튼을 비활성화한다. 기본 재생 장치는 헤드셋으로 제안하고, 종료
후 PC 스피커 재생은 사용자의 명시적 재생 동작에서만 허용한다.
빈 목록에는 업로드 버튼을, USB 실패에는 진단 버튼을, API 실패에는 재시도 가능 여부를 보여준다. 기술 로그 대신 ‘상대
음성을 받지 못했습니다’처럼 원인과 다음 행동을 함께 표시한다.


### 시작 버튼 활성화 조건

필수 열 유효, 대상 1명 이상, 거부 제외 완료, 회사명·음원 준비, 장치 실통화 검증 유효, 연결 에이전트 인증, 비밀키 설정
검사, 다른 통화 없음이 모두 충족되어야 한다.

### 컴포넌트

버튼은 기본·보조·위험 세 종류로 구분한다. 위험 버튼은 정확한 동작을 이름으로 표시하고 실행 중에도 접근 가능하게 한
다. 표에는 고정 헤더, 선택 체크박스, 정렬, 페이지 이동 또는 가상 스크롤을 제공한다.
상태 배지는 색과 글자를 함께 쓴다. ‘통화중’, ‘확인완료’, ‘미확인’, ‘연락거부’, ‘부재중’, ‘실패’를 구별한다. 연락거부와 단순
통화불가를 같은 상태로 쓰지 않는다.
날짜는 YYYY-MM-DD로 표시하고 통화 시각에는 한국시간 기준을 명시한다. 화면의 빈 값은 ‘미확인’, 출력 파일의 빈 날
짜는 빈 셀로 표현한다. 전화번호는 숫자용 고정폭 글꼴을 고려하되 앞자리 0을 유지한다.


### 접근성과 입력

키보드만으로 업로드·목록 선택·검수·중단을 수행할 수 있어야 한다. 초점 테두리를 지우지 않고 상태 변화는 스크린리더에
서도 읽히게 한다. 표준 본문 대비는 WCAG AA 수준을 목표로 검증한다. 클릭 영역은 최소 40px 높이로 제안한다.
문제 행에는 해당 셀과 오류 설명을 함께 표시한다. 로딩 중에는 중복 제출을 막고, 완료 알림은 작업 결과와 다운로드 위치
를 알려준다.


### 음성 디자인

통화마다 선택한 남녀 음성을 유지한다. 음원 간 음량 차이를 정규화하고 시작 무음은 줄이되 단어 첫소리를 자르지 않는
다. 불필요한 장문 안내 대신 한 질문에 한 목적을 둔다.
ARS 녹음과 Gemini 목소리가 완전히 같다고 보장하지 않는다. API가 제공하는 목소리 가운데 가까운 것을 선택해 이질감
을 시험하고, 음성 복제가 필요하면 별도 범위로 검토한다. ‘김태희 실장’은 역할 이름이며 유명인 음성 복제 요구로 해석하
지 않는다.


### 금지하는 표현

녹음 저장만 성공했는데 ‘통화 성공’이라고 표시하지 않는다. 발신 연결·음성 수신·음성 전달·일정 확인·저장 완료를 각각 판
정한다. 확인되지 않은 날짜에 체크 표시를 붙이지 않는다.


## 08 기술설계서


### 권장 구조와 조건

웹 UI → 백엔드 API·DB·비공개 녹음 저장소 → 인증된 PC 에이전트 → 검증된 A24 제어·음성 어댑터로 구성한다. PC 에
이전트는 ARS 캐시·상태기계·장치 제어·오디오 버퍼를 맡고 웹은 목록과 검수를 담당한다.
배포 제안은 React와 TypeScript 웹, FastAPI 서버·에이전트, PostgreSQL, 비공개 객체 저장소다. 단일 PC 설치 프로그램
은 에이전트를 시작하고 웹 화면을 연다. 이 기술 선택은 설계 제안이며 구현 또는 기존 프로젝트 확인 결과가 아니다.


### 먼저 검증할 USB 경로

Android 공식 문서는 통화 음성 캡처에 특별 권한 조건을 설명하고 USB 개발 모드 자체는 오디오를 지원하지 않는다고 명
시한다[S1][S2]. 이로부터 일반 USB 디버깅 케이블과 발신 제어만으로 양방향 실통화 음성이 된다고 결론낼 수 없다.
Android USB 호스트 오디오는 호환되는 USB 오디오 주변기기를 전제로 한다[S3]. 이는 A24가 일반 PC 연결에서 통화
오디오 장치로 동작한다는 증거가 아니다. 별도 장치·제조사 기능·기존 전용 어댑터의 가능성은 실물 확인 전 미확인이다.
A24 모델 세부번호・Android 및 One UI 버전・통신사・PC OS・케이블・장치 목록을 기록하고 동일한 환경에서 반복 검증한다.

UI 버전·통신사·PC OS·케이블·장치 목록을 기록해 동일 환경에서 반복 검증한다.


### 장치 어댑터 계약

capabilities는 dial, hangup, answer_detection, rx_audio, tx_audio, recording을 각각 supported 또는
unsupported 또는 unknown으로 반환한다. start_call은 발신 요청 식별자를 만들고 실제 answered 이벤트와 구분한다.
read_rx는 상대 음성 프레임과 순번·단조시각을 전달한다. write_tx는 송신 경로에 프레임을 넣는다. accepted 또는
drained는 원격 청취 성공을 뜻하지 않으며 실기기 검증 결과와 분리한다. 연결 손실 시 기본 스피커로 자동 전환하지 않고
송출과 다음 발신을 차단한다.


### 빠른 응답 경로

RX 전용 스트림 → VAD와 스트리밍 STT → 현재 질문에 한정한 의도·날짜 추출 → 신뢰도와 문장 완료 검사 → ARS 캐시
→ TX 순서다. VAD의 소리 감지만으로 답을 선택하지 않는다. 중간 STT로 후보를 준비하되 날짜 확정에는 안정된 최종 결
과와 재확인을 요구한다.
발화 종료 검출은 초기 250~500ms 무음 범위에서 시험하고 말속도·망 잡음에 맞게 조정한다. 고정 1초 대기를 매 턴 추가
하지 않는다. STT 공급자는 한국어 전화음질로 비교 후 선정한다. 모든 대화를 생성형 AI에 먼저 보내지 않는다.


### 예외 AI와 경합 제어

예외가 확정된 턴만 Gemini Live 세션에 필요한 맥락을 전달한다. 일반 ARS는 AI 응답을 기다리지 않는다. 예외 응답 동안
송출 소유권을 AI로 넘기고 같은 턴 ARS를 막는다. 취소 토큰과 턴 번호가 지난 AI 오디오는 폐기한다.
Gemini Live는 실시간 오디오 상호작용을 지원하며 실제 모델·SDK·입출력 형식은 배포 시 공식 문서로 확인해 고정한다
[S4]. 연결·응답·세션 종료 시간을 계측한다. 정책 제안은 예외 질문당 최대 2문장, 10초 내 실패 처리, 통화당 예외 2회 이
후 상담 요청이다.


### 녹음과 장애 복구

RX와 실제 TX 송출 스트림을 분리 기록한 뒤 시간축에 맞춰 2채널 파일과 재청취용 파일을 만든다. 원격이 실제로 들은 음
성과 TX 버퍼가 같다고 가정하지 않는다. 종료 시 파일 길이·누락·해시를 검사한다.
암호화된 로컬 임시 저장 후 서버 수신 확인이 되면 로컬 파일을 정책에 따라 지운다. 서버 장애 때는 대기열을 멈추고 결과
를 로컬 저널에 기록한다. 재연결 후 이벤트 ID로 중복 없이 동기화하며 자동 재발신하지 않는다.


### 검증할 가설

H1: 해당 A24 환경에서 USB만으로 RX·TX가 가능하다. 근거 강도 낮음, 일반 문서만 있고 기기 증거 없음. 대안 가설은 전
용 권한·추가 장치가 필요하다는 것이다. 담당은 장치 개발자, 승인된 테스트 통화 10회 전부 양방향·무음·녹음 통과 시 해
당 환경에서 부분검증한다.
H2: 상태별 ARS와 스트리밍 인식으로 일반 응답 p95 1.5초를 달성한다. 미검증이며 지연 대부분이 망 또는 STT일 가능성
도 있다. 담당은 음성 개발자, 100개 이상 발화에서 원격 청취 시각까지 측정해 판정한다.
H3: 날짜 재확인으로 오기입을 방지한다. 미검증이며 동의 인식 오류가 경쟁 원인이다. 담당은 QA, 부정·정정·모호한 날짜
를 포함한 100개 사례에서 잘못된 자동 반영 0건을 요구한다.

### 날짜 저장 트랜잭션

후보 추출 → 후보 저장 → 확인 질문 → 명시적 동의 이벤트 → observation 확정 → caregiver 날짜 변경과
schedule_changes 추가를 하나의 트랜잭션으로 수행한다. 동의 이벤트는 같은 통화·같은 날짜 후보·같은 턴에 연결되어
야 한다.
caregiver.version을 조건으로 갱신하고 불일치하면 409 충돌로 검수한다. 확정일을 바꾸기 전 새 값이 출처 날짜와 일치
하는지 검사한다. API 재전송은 동일 confirmation_event_id에 한 번만 반영한다.


### 연락거부 모델

거부는 통화 완료 여부와 별도로 즉시 영속화한다. 같은 전화번호가 재업로드되더라도 차단되게 조직 범위의 정규화 전화
번호 HMAC을 사용한다. 단순 해시는 전화번호 대입에 취약하므로 서버 비밀값을 사용한다.
유효 차단을 큐 등록 때와 발신권 획득 때 확인한다. 해제는 관리자 사유와 근거를 남기며 기존 차단 기록을 삭제하지 않는
다. 이미 진행 중인 통화는 송출을 멈추고 정중히 종료한다.


### 색인과 잠금

call_sessions(target_id, started_at), call_events(call_id, seq), campaign_targets(campaign_id, state),
recordings(expires_at), contact_blocks(organization_id, phone_hash)에 색인을 둔다. 단말의 활성 발신권은 유일 제
약과 만료 가능한 임대로 보호한다.
임대 만료가 즉시 재발신 허가를 뜻하지 않는다. A24 실제 통화 상태를 조회해 IDLE임을 확인한 뒤 새 통화를 허용한다.
DB가 통화 종료를 기록해도 단말이 아직 통화 중일 수 있다.


### 보관과 삭제

녹음·전사·업로드 원본의 보관 기간은 관리자 정책으로 결정한다. 기간 미설정이면 실제 운영을 활성화하지 않는다. 만료
시 객체 파일과 연결 메타데이터를 순서대로 정리하고 실패 재시도·감사 기록을 남긴다.
연락거부를 계속 이행하는 데 필요한 최소 차단 정보의 보관은 녹음 보관과 별도로 정한다. 원본·로그·백업·내려받은 엑셀
까지 삭제 정책의 적용 범위를 문서화한다. 이는 설계 요구이며 법적 보관 기간을 확정한 것이 아니다.


## 10 API 명세서


### 공통 계약

다. 조직 ID는 서버 인증 정보에서 결정하고 클라이언트가 보낸 값만 신뢰하지 않는다.
발신·확정·내보내기 생성 요청은 Idempotency-Key가 필수다. 같은 키와 같은 본문은 같은 결과를 반환하고, 같은 키에 다
른 본문은 409로 거절한다. 키 범위는 조직·사용자·경로이며 실행 기록과 함께 보존한다.

### 대표 요청과 응답

POST /campaigns 요청 예시: {"target_ids":["uuid-1"],"voice_pack_version":"female-v1"}. 실제 구현에서는 UUID
형식 검사를 수행한다. 응답 예시: {"campaign_id":"uuid-c","accepted_count":1,"excluded_targets":[]}.
날짜 확정 요청 예시: {"observation_id":"uuid-o","evidence_event_id":"uuid-e","expected_version":4}. 서버는 이벤
트에서 명확히 확인된 날짜를 읽어 반영하며 AI가 임의로 보낸 date만으로 저장하지 않는다.
오류 형식은 {"error":{"code":"DEVICE_AUDIO_UNVERIFIED","message":"통화 음성 경로 검증이 필요합니
다","request_id":"...","details":{}}}이다. 메시지와 로그에 전화번호·API 키를 넣지 않는다.


### 오류와 비동기 처리

400 형식 오류, 401 인증 없음, 403 권한 없음, 409 상태 또는 버전 충돌, 422 필수 열·날짜 의미 오류, 429 요청 제한,
503 에이전트·AI·DB 불가를 사용한다. 202는 명령 접수이며 실제 발신 또는 종료 완료를 뜻하지 않는다.
파일 검증과 엑셀 생성은 작업 ID로 조회한다. 다운로드 링크는 권한 검사 후 발급하며 엑셀에 영구 공개 녹음 URL을 넣지
않는다.


### 실시간 이벤트 계약

웹은 인증된 이벤트 채널에서 campaign.progress, call.state_changed, transcript.partial, transcript.final,
schedule.candidate, schedule.confirmed, contact.blocked, recording.ready, device.disconnected를 받는다.
공통 봉투는 event_id, call_id, seq, turn_id, occurred_at, type, payload다. 재연결은 last_event_id로 복구하고 중복
event_id를 무시한다. 확정과 차단 이벤트는 DB 커밋 이후 발행한다.


### PC 에이전트 연결

에이전트는 서버로 outbound WSS 연결을 유지하고 짧은 수명의 장치 토큰으로 인증한다. 명령에는 command_id·대상
단말·만료시각·서명 검증을 적용한다. 서버가 전화번호를 검증하고 한 번만 발신권을 발급한다. 임의 웹사이트에서
localhost 발신 명령을 호출하도록 열어두지 않는다.
녹음 업로드는 승인된 객체 키와 해시·길이로 완료 확인하며 같은 업로드 재전송을 중복 파일로 처리하지 않는다. STT와
Gemini 키는 브라우저 번들이나 GitHub에 저장하지 않는다.

### A24 필수 실통화 시험 절차

1. PC 마이크와 모든 스피커 루프백 경로를 끄고 A24·USB 구성만 남긴다. 실제 장치 경로 ID를 저장한다.
2. 승인된 원격 단말로 발신해 상대에게 시험 문장 10개를 읽도록 한다. STT 입력과 RX 녹음에서 동일 내용을 확인한다.
3. 남녀 ARS를 각각 보내고 원격 상대가 들은 문장을 기록한다. PCM accepted 로그만으로 통과하지 않는다.
4. 원격 시험 단말의 녹음 또는 공동 계측으로 발화 종료와 응답 시작의 시간을 측정한다. 망 지연을 포함한 원격 청취 기준
을 유지한다.
5. 케이블 제거·재연결·재부팅·반복 통화에서 재현성을 확인한다. 일반 PC 출력 장치에 오디오 스트림이 열리지 않았는지
도 확인한다.


### 날짜 판정 세트

“25일까지 근무”는 종료일만 저장한다. “26일부터 가능”은 후보이며 확인 질문의 명시적 동의 후 반영한다. “아니, 27일”은
후보를 정정한다. “잘 모르겠어요”는 미확인이다. “연락하지 마세요”는 날짜 질문을 중단하고 차단한다.
“오늘 안 돼요”는 오늘 통화 불가일 수 있으므로 영구 연락거부로 단정하지 않는다. 음성사서함·자동 안내·동명이인·제3자
응답은 일정 확정 대상으로 삼지 않는다.


### 출시 판정

USB 양방향·무음·녹음 필수 시험 전부 통과가 첫 관문이다. 일반 응답 지연 목표는 100개 이상 발화에서 p50·p95·실패율
을 함께 보고한다. 성공한 통화만 골라 측정하지 않는다.
날짜 검증 100개 사례에서 잘못된 자동 반영 0건, 연락거부 재발신 0건, 권한 우회 0건이 필수다. 표본 통과는 전체 무오류
를 보장하지 않으므로 초기 운영은 검수 비율을 높인다. 미통과 항목은 출시 완료로 처리하지 않는다.


## 12 운영 배포 문서


### 저장소와 배포 구조

제안 저장소는 apps/web, services/api, apps/agent, packages/contracts, docs/01~12, tests/fixtures,
infra, .github/workflows로 나눈다. 이번 ZIP의 docs 문서는 이 구조에 옮겨 버전 관리할 수 있다. 아직 실제 GitHub 저
장소를 만들거나 연결하지 않았다.
개발용·시험용·운영용 환경과 키를 분리한다. PR에서 형식 검사·단위 시험·계약 시험·엑셀 회귀 시험·비밀키 탐지를 수행한
다. 승인된 릴리스 태그로 서버와 서명된 설치 파일을 빌드하고 이전 버전 복귀 경로를 유지한다.


### 단일 실행 배포

운영자는 설치 후 AICC 바로가기 하나만 실행한다. 실행기는 중복 프로세스를 방지하고 PC 에이전트 상태를 확인한 후 웹
관리화면을 연다. 초기 드라이버 설치나 A24 권한 설정은 별도 초기 설정이며 매 통화마다 요구하지 않도록 한다.
단일 실행을 ‘브라우저만으로 통화 가능’과 혼동하지 않는다. A24 USB 음성 경로가 입증되지 않으면 설치 프로그램이 있어
도 실통화 기능은 비활성 상태다. PC가 꺼져 있거나 USB가 빠지면 웹 단독으로 A24 통화를 수행할 수 없다.


### 일일 운영 절차

업무 시작: 장치·음원·녹음 저장 여유·API 상태 확인 → 명부 검증 → 연락거부 제외 → 승인된 대상 선택 → 발신 시작.
업무 종료: 모든 통화 종료 확인 → 미확인 결과 검수 → 엑셀 다운로드 → 업로드 행 수와 결과 합계 대사 → 녹음 업로드 누
락 확인 → 에이전트 종료.
통화 허용 시간·재시도 간격·최대 시도·최대 통화 길이는 운영자가 정책으로 설정한다. 정책 미설정 상태에서는 실제 자동
발신을 시작하지 않는다. 여기서 특정 시간을 법적 허용시간으로 단정하지 않는다.


### 장애 대응

장치 장애는 발신 큐 정지, RX·TX 경로 확인, A24 통화 상태 확인 순서다. 네트워크 장애는 신규 발신을 중단하고 로컬 저
널을 보존한다. AI 장애는 준비된 안내 후 검수 대상으로 남기며 일반 ARS까지 무조건 중단할 필요는 없지만 날짜 확인 기
능이 불안정하면 종료한다.
녹음 저장 실패는 사용자 화면에 분명히 표시하고 결과와 녹음 상태를 분리한다. 통화가 성공했더라도 녹음이 정상이라고
표기하지 않는다. 원인을 해결한 뒤에만 운영자가 재개한다.


### 개인정보와 녹음 운영 결정

본 문서는 녹음·개인정보 처리의 법률 적합성을 확정하지 않는다. 실제 운영 전 회사명·처리 목적·녹음 안내·권한·보관과 파
기·AI 외부 전송 범위·필요한 고지와 동의 방식을 담당자가 확정한다.
개인정보와 환자 의료정보는 AI에 불필요하게 보내지 않는다. 상대가 환자 정보나 일자리 조건을 질문하면 일정 확인 범위
밖임을 안내하고 전담 실장 연락 요청으로 남긴다. 녹음 거절 시 기본 정책은 자동 통화를 종료하고 수동 연락 요청으로 기
록한다.


### 모니터링과 백업

캠페인별 발신·응답·일정 확인·거부·실패 건수, ARS와 AI 지연, RX 무음 비율, 녹음 누락, 재접속을 모니터링한다. 전화번
호와 대화 전문은 일반 오류 로그에서 제거한다.
백업은 암호화하고 접근권한을 제한한다. 임시 목표는 DB 복구 시점 24시간 이내, 복구 시간 4시간 이내이며 운영 규모 확
인 후 정한다. 복원 시험에서 녹음 접근권한·연락거부·수정 이력을 확인한다. 복원 뒤 자동 발신은 기본 중지 상태로 시작한
다.
